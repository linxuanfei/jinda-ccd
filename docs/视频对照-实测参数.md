## 6. 第二个视频（`2017538603.mp4`，960×512 / 9分15秒）：规则设置的真值

> 这个视频绝大部分时间是一个**最大化后的单相机画面**在连续跑（OK 稳定，偶发 NG），
> 但在 **300 秒**处右侧面板切到了「规则设置」页签，把**判定规则的真实数值**暴露出来了——这是目前最有价值的一帧。

### 6.1 规则设置面板（实测，t=300s）

| 字段 | 实际值 |
| --- | --- |
| 起始对象 / 终止对象 | **04 / 04** |
| 附属 | ☐ 未勾 |
| 位置 | **垂直最大**（灰显） |
| **类型** | **X方向距离** |
| **基准** | **03**（另有"生成组合基准"按钮） |
| **设计值** | **1 mm** |
| **容差上限 / 容差下限** | **+0.08 mm / −0.08 mm** |
| 结果取绝对值 | ☐ 未勾（右侧输入框显示 1） |
| 数据分组 | 组别空；共面度/最小值/GAPI值 均未选 |
| 颜色识别 | 最小面积 1000 Pixel、相关类型 RGB、背景类型 黑、相关系数 **70%** |
| 缺陷检测 | ☐ 开启检测；灰度差 **40**、缺陷面积 **50** Pixel、腐蚀半径 **1** Pixel、轮廓路径空 |

→ **判定口径定死了**：对象 04 相对基准对象 03 的 X 方向距离，**1 mm ± 0.08 mm**。
这正好解释了操作说明里那句「视频中设定值为 1，现检测结果为 1.433」——未标定时实测 1.433（超差 +0.35），
**改标定把实测拉回 1 附近**，规则才判 OK。

### 6.2 上一轮判断需要更正 ❗

上一轮（视频1）我写「容差很宽：7626 对 10000 仍判 √」。看到规则设置后要更正：

- **距离规则的实际容差是 ±0.08mm（±8%），很紧**；
- 面积那条 10000 vs 7626 还能判 √，说明**面积规则另有口径**（可能面积列只作参考、或面积容差单独设很大），**不能当成"容差宽"的证据**。
- 结论：**判定必须以"设计值 ± 各自容差"逐项设，不能统一放宽**。

### 6.3 画面标注（实测）

- 一排 8 个针脚，每针脚一个**窄框**，框左上角绿色**两位编号**：`02 03 04 05 06 07 08 09`。
- **当前编辑中的对象（03）框变成红色** —— 印证「选中显示红色」（R-05）。
- 一排框下方有一条**绿色横线贯穿**（疑似检测区域边界或基准线，待确认）。
- 左上角大号绿色 `OK`；NG 时变红。

### 6.4 单画面最大化（实拍证据）

视频 0~15 秒：先是 4 个空画面（**未连相机时是白色空白**），随后某一台相机连上、**把单画面最大化铺满**，
右侧检测设置面板与底部状态栏仍在。

→ 证明 R-19 要的「双击单画面最大化/还原」就是现场习惯用法，不是我猜的。

### 6.5 状态栏 `ratio` 是什么（疑问解决）

| 视频 | 画面布局 | ratio |
| --- | --- | --- |
| 视频1 | 4 分屏 | **0.4383** |
| 视频2 | 单画面最大化 | **1.3844 / 1.9638**（随缩放变化） |

→ `ratio` = **显示缩放倍数**（画面放大/缩小比例），**不是标定比例**。上一轮在 §5 把它列为"疑似标定比例"，现予更正。

### 6.6 视频2 额外确认的

| # | 事实 | 影响 |
| --- | --- | --- |
| 1 | 未连相机 → 画面白色空白 | 我们"未连接"时应给灰色提示，不要显示白色误导 |
| 2 | 单画面最大化时右侧面板/状态栏仍在 | 布局是"画面区最大化"，不是全屏 |
| 3 | 编号两位数、按对象递增；选中框红色 | R-05 / R-23 |

## 3. HPro 参数段已破译（现在真读了）

参数行第 7 段：

```
2 2 2 2 999999 25 0 0 0 -1 0.000 255.000 0.000
└最小宽┘└最小高┘└maxArea┘└minArea┘        └下限┘ └上限┘
```

判定行（模式 1/2）：

```
1 1 0 -1 -0.100 0.080 0.080 100 99999 0 0 0   → 标称 -0.100 ± 0.080
2 0 0 -1 1.000 0.080 0.080 100 99999 0 0 0    → 标称  1.000 ± 0.080
```

评分行：

```
0 200 0 0.85   → 二值化阈值 200、模板相关系数 0.85
```

> **视频里看到的"下阈值 111 / 上阈值 255"**：HPro 里存的是 `0.000 / 255.000`，
> 说明原程序用的是**自动阈值**（0=自动），111 是运行期算出来的。我方导入时标 `_auto_threshold=true`，
> 阈值不再当 0 用（默认 128 或评分行的 200），现场用红蒙版重新调。

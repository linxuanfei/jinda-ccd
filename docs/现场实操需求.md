## 0. 现场实际调机流程（4 步）

```
① 画水平基准线 ──► ② 画检测框(可批量) ──► 设抓取位置 + 调阈值
                                            │
                    ④ 单次检测看结果 ◄── ③ 加检测规则 → 加跟踪框 → 跟踪设置
                            │
                            └─► 尺寸与实际不符 → 改相机标定值
```

| 步 | 现场原话 | 要点 |
| --- | --- | --- |
| ① | 「画水平基准线，点了直线之后…始终是往右水平延伸的」 | 原厂强制水平；**现场确认线要自己画、且要能任意角度**（R-04 保留，去掉强制水平） |
| ② | 「选择矩形按住 Ctrl 可以同时画多个检测框…全部选中在菜单栏可以快速操作同时修改所有检测框大小（上对齐，下对齐，左对齐，右对齐，等大小，水平等间距，垂直等间距）」 | **多选 + 批量对齐**是调机效率的核心 |
| ② | 「设定检测框抓取位置（定位位置），抓取位置都已黑白为主（黑色底部、白色底部、白色中下、黑色中下等等）…阈值最小为 0，最大为 255，最大可用阈值为 254…红色范围为阈值调节之后屏蔽掉的地方」 | **抓取方向**（黑/白 × 底/中/上）+ **判断极性可视化** |
| ③ | 「主要检测方式为 X 水平、Y 垂直方向，间距为 X 方向距离，贴板为 Y 方向距离…规则预览内能看到现有设定的所有规则」 | 规则分 X/Y 两类语义 |
| ③ | 「要增加一个跟踪框，因为机台运行的时候不会百分百把产品都放在同一个位置…点击菜单栏上的跟踪设置，起始于终止对象按顺序填入之后，跟踪对象为跟踪框」 | **跟踪框 = 生产稳定性的前提**，不是可选 |
| ④ | 「检测结果与实际尺寸有偏差…修改相机标定，X 水平，Y 为垂直，视频中设定值为 1，现检测结果为 1.433，点击菜单栏相机标定按钮修改标定值」 | 标定值**可直接改**，X/Y 分开 |

## 1. 需求清单（R-01 ~ R-22，均为必须）

> 状态取值：✅ 已有 · ⚠️ 部分 · ❌ 缺失。「差距项」见 [`功能差距.md`](功能差距.md)。

### A. 主界面

**R-01 主界面为操作总入口** ✅
- 要求：画面区 + 参数显示 + 快捷工具栏 + 菜单入口 + 状态提示栏；打开即可完成**相机选择、画面查看、检测启停、结果查看**。
- 现状：已有 6 机位同屏 + 右侧统计/检测项/结果表 + 状态栏（`VisionApp` 主界面）。
- 差距：布局自由度（R-19）。

### B. 相机

**R-02 相机数量与品牌在「超级管理员」里设置** ❌ ｜ 差距 D-02 / D-15
- 要求：进入超级管理员 → 修改**相机数量**与**相机品牌**（原厂 19 种型号，见 `原厂功能说明` §6）；另有比例尺寸/序列号。
- 现场确认（2026-11-16）：本线相机为 **MindVision 迈德威视**（型号待补），适配代码已就绪 → [`相机接入-MindVision.md`](相机接入-MindVision.md)。
- 现状：相机（帧源）写在 `config/line.json` 的机位里，界面"产线配置"可改类型（合成/图片/UVC/RTSP），**无工业相机品牌选择**。
- 验收：界面能选品牌+数量，保存后重建机位；未接 SDK 的品牌给出明确提示而不是崩。

**R-03 相机参数：曝光/增益/帧率/触发模式** ❌ ｜ 差距 D-02
- 要求：对**选中的相机**单独调节曝光、增益、帧率、**触发模式**；原话「相机默认为**硬件触发**模式，相机需要调整时要**改为连续模式**」——否则调参时画面不刷新。
- 现状：`SourceInfo/meta` 只透传；MindVision 已能通过配置传 `exposure_us/gain_db/fps/trigger`，**还差界面控件与随机位持久化**。
- 验收：改曝光/增益/帧率即时生效；触发模式可切 硬件/连续；参数随机位保存、重启恢复。

### C. 检测框（ROI）

**R-04 直线（线形 ROI）工具** ✅ **保留（P0）** ｜ 差距 **D-29**
- 现场反馈 ①（2026-11-16）：「直线水平这个我们自己画」→ **不强制水平锁定**（鼠标怎么偏都变水平那种不要）。
- 现场反馈 ②（2026-11-16）：「**画线的功能留着**，我们产品种类不一样，画的地方和使用都有不一样的需求」
  → 线形 ROI **必须保留且通用**，不能只当"水平基准线"用。
- 要求：一条线可以在画面**任意位置、任意角度**画（不同产品、不同工位用法不同）；
  需要时能精确定向（`Shift` 吸附 0°/45°/90°），但默认自由角度。
- 现状：**只有矩形 `Rect`，没有线**（.HPro 导入时靠 `line_roi_thickness` 把线加厚成细矩形规避）。
- 常见用法（待现场逐条确认，见 §5 #6）：
  1. **基准线**：作为 X/Y 方向的参考（测距、参差度都相对它）；
  2. **点到线距离**：每个 PIN/边到线的偏差（参差度、共面度）；
  3. **找边/卡尺**：沿线方向找灰度跳变，取交点或边位置；
  4. **对齐/摆正**：用线的角度判断产品有没有歪。
- 验收：能画任意角度的线；能选中（红色）、拖动、拖端点改角度/长度；线可被规则引用；随配方保存。
- **调试员照片线索**：相机1 画面里有一条**横线贯穿整排 PIN**，每个 PIN 在线上取点（疑似基准线 + 每点相对基准线的偏差/位置）。
  若确认如此，则 §5 #6 的 **②点到线距离** 就是必需算子（不是可选项）。

**R-05 选中显示红色 + 右键拖动移动** ⚠️ ｜ 差距 D-29
- 要求：「选择之后，选中的框显示**红色**，**右键点击移动**」。
- 现状：可选、可拖框内移动、拖四角缩放、Delete 删除；选中高亮色与右键行为需按现场习惯对齐。
- 验收：选中框红色描边；按住右键拖动整框移动；不影响左键画画。
- **视频2 实测**：8 个针脚框全部绿色描边 + 绿色两位编号，**当前编辑的 03 号框变红色** → 与"选中显示红色"一致。

**R-06 矩形 + Ctrl 连画多个检测框** ❌ ｜ 差距 **D-30**
- 要求：按住 `Ctrl` 可连续绘制多个矩形，不需要每次重新点工具。
- 现状：一次画一个，画完要重新点"新增 ROI"。
- 验收：Ctrl 保持时连续出框；Esc/松 Ctrl 退出连画。

**R-07 多框批量编辑：对齐 / 等大小 / 等间距** ❌ ｜ 差距 **D-30**
- 要求：先调好首尾两个框，再全选，用菜单栏一键：**上对齐、下对齐、左对齐、右对齐、等大小、水平等间距、垂直等间距**。
- 现状：只能逐个改数值。
- 验收：全选后 7 个命令生效且可撤销；等间距按首尾框位置均分。

**R-08 抓取位置（定位方向）** ⚠️ ｜ 差距 **D-31**
- 要求：给每个检测框设"抓取位置"，**以黑白为主**：`黑色底部 / 白色底部 / 白色中下 / 黑色中下 …`（即：找亮还是找暗 + 在框内的哪个区位找边界）。
- 现状：`find_blobs` 只有 `threshold_mode = dark/light`（明暗极性），**没有区位/方向维度**。
- 验收：下拉可选 8 种组合（黑/白 × 底/中下/中/上）；选定后取点位置与现场一致。
- **视频实测（2026-11-16）**：现场选的是 **白色中上**；同时勾了 **强制水平 + 强制竖直 + 最大区域**，
  最小宽度 2 / 最小高度 2 / 最小面积 25 / 最大面积 999999 / 最小圆度留空。→ 这几个是默认值的最优起点。

**R-09 阈值有效区间 1~254** ⚠️ ｜ 差距 D-31
- 要求：「阈值最小 0 最大 255，**最大可用阈值 254**；调到 **0 或 255 会抓取错误**」。
- 现状：`threshold` 无区间校验，填 0/255 不会被拦。
- 验收：界面限幅 1~254 并提示；配方校验拒绝越界值。
- **视频实测（2026-11-16）**：现场是**区间**用法——下阈值 **111**、上阈值 **255**（不是单阈值）。

**R-10 阈值屏蔽区域可视化（红色）** ❌ ｜ 差距 D-31
- 要求：「**红色范围为阈值调节之后屏蔽掉的地方**」——调阈值时实时看到哪些像素被排除。
- 现状：无二值/屏蔽预览。
- 验收：调阈值时叠加红色遮罩，实时刷新；可开关。

### D. 规则

**R-11 检测方式：X 水平 / Y 垂直（间距 / 贴板）** ⚠️ ｜ 差距 D-05 / D-26
- 要求：「主要检测方式为 **X 水平、Y 垂直**方向；**间距 = X 方向距离**，**贴板 = Y 方向距离**」。
- 现状：`distance_pp` 是任意两点距离（无方向语义）；.HPro 导入靠 `hpro_types.json` 猜 type 号。
- 验收：规则类型下拉有 X间距/Y贴板（含方向约束）；导出/导入与现场语义一致。
- **视频2 实测（t=300s）**：类型 = `X方向距离`；起始/终止 = `04/04`；基准 = `03`；
  **设计值 1 mm、容差 ±0.08 mm**。→ 判定必须是"设计值 ± 容差"，且容差逐项设（这条是 ±8%，很紧）。

**R-12 规则预览：列出全部已设规则** ⚠️ ｜ 差距 **D-32**
- 要求：「设置好规则在**规则预览**内能看到现有设定的**所有规则**」（原厂还有公差统计面板）。
- 现状：右侧检测项列表可看单项参数，但无"全部规则一屏总览 + 公差统计"。
- 验收：一屏表格列出 规则/对象/设计值/上下公差/实测；可点击定位到项。

**R-13 检测结果显示在画面上** ✅
- 要求：正常/不良直接标 OK/NG，并展示检测框、缺陷位置、检测数值。
- 现状：画面 OK/NG 大字 + 每项框与数值 + 右侧结果表；NG 图存盘。
- **视频实测（2026-11-16）**：结果表列 = `对象 / 设计值 / 实测 / 面积 / NG次数 / √`；
  面积规则 设计值 **10000.0**、实测 **7626.0**、判 √ 合格、NG次数 逐对象累计 **2**。
  → 说明判定是"实测 vs 设计值 + 宽容差"，且 NG 次数按对象分别累计。

### E. 跟踪（生产稳定性核心）

**R-14 必须增加跟踪框** ❌ ｜ 差距 **D-33（P0）**
- 要求：「机台运行时不会 100% 把产品放在同一位置，**增加跟踪框**是为了保证检测框都在正确范围」。
- 现状：无跟踪；产品位置一偏，检测框就框错。
- 验收：放一个跟踪框（框住产品上的稳定特征），产品平移/小角度旋转 2~5 mm 内，各检测项数值波动 < 公差 1/3。

**R-15 跟踪设置：起始/终止对象 + 跟踪对象** ❌ ｜ 差距 **D-33（P0）**
- 要求：「点击菜单栏**跟踪设置**，**起始、终止对象**按顺序填入之后，**跟踪对象为跟踪框**」。
- 现状：无。
- 验收：能指定"对哪些对象做跟踪补偿"和"用哪个框当跟踪基准"；保存进配方。

### F. 标定

**R-16 相机标定：X/Y 分开、标定值可直接改** ⚠️ ｜ 差距 **D-34**
- 要求：「X 为水平、Y 为垂直」「视频里设定值为 1，实测 1.433 → 点**相机标定**改标定值，调到需求结果」。
- 现状：两点标定算 `mm_per_px`（单一比例，随配方保存）；无 X/Y 两个系数、无"直接改数值"入口。
- 验收：标定面板可分别填 `X mm/px`、`Y mm/px`；也能"输入实测值 + 期望值"反算；改动立即生效。

### G. 菜单

**R-17 文件菜单：工程管理 + 导出检测记录** ⚠️ ｜ 差距 D-14
- 要求：新建方案 / 保存 / 读取 / **导出检测记录**，换产品直接加载。
- 现状：配方 新建/打开/保存/另存为 ✅；导出检测记录 ❌（只有 CSV 落盘）。

**R-18 编辑菜单：增删复制移动 + 复制规则 + 撤销/重做** ⚠️ ｜ 差距 D-28
- 要求：新增/删除/**复制**/移动检测框，**复制检测规则**，**撤销/重做**。
- 现状：检测项有 新增/复制/删除/上移/下移 ✅；撤销/重做 ❌；多选批量 ❌（R-07）。

**R-19 视图菜单：多窗口调出与自由排布** ⚠️ ｜ 差距 D-16
- 要求：可单独调出相机画面窗口、自由排布子窗口、适配屏幕习惯（原厂：层叠/平铺/排列图标/停靠）。
- **调试员照片观察（2026-11-16）**：原厂 4 路是 **MDI 浮动子窗口**——各自带标题栏（相机1/2/3/4 + 最小化/最大化/关闭），
  可以**拖动、重叠**；调试员实际就是把某一路**拖大/最大化**去对细节。
- 现状：固定 3×2 网格，单路画面不能放大（只有鼠标滚轮缩放）。
- 要做：① **双击单画面 = 最大化/还原**（最高性价比）；② 可选"自由布局/停靠"（P2）。
- **视频2 实拍**：前 15 秒就是从 4 分屏切到**单画面最大化**（右侧面板与状态栏保留），证明这是现场常规用法。

**R-20 系统菜单：语言 / 日志路径 / 自动保存周期 / 通讯端口 / 外部信号 / 版本信息** ⚠️ ｜ 差距 D-03 / D-35
- 要求：这几项都是系统级设置，现场要能自己改（尤其**日志存储路径**、**自动保存周期**、**外部信号对接 PLC 触发 / IO 信号**）。
- 现状：`config/app_settings.json` 已有 记录/输出(串口/TCP)/报警 设置；缺 日志路径、自动保存周期、版本信息显示；外部信号触发 ❌（D-03）。

**R-21 工具栏高频操作** ⚠️ ｜ 差距 D-36
- 要求：打开相机 / 启动检测 / 停止检测 / **抓拍原图** / **保存截图** / **清除结果** / **一键运行方案**。
- 现状：开始/停止/单帧/清空计数 ✅；抓拍原图、保存截图、清除结果、一键运行 ❌。

### H. 权限

**R-22 三级权限：生产 / 管理员 / 超级管理员** ⚠️ ｜ 差距 D-15
- 要求：
  1. 「**打开软件直接生产，不需要修改参数，无需登录**」——默认就是生产态；
  2. 「需要**修改/增加检测框或检测规则**要登录**管理员**」；
  3. 「需要**修改相机数量、相机品牌与比例尺寸**要登录**超级管理员**」。
- 现状：操作员/工程师两级（默认工程师全权限、可设密码），**与现场习惯相反**（现场默认锁死、要改才登录）。
- 验收：启动=生产态（只运行、不能改框/规则）；输入管理员密码解锁编辑；超级管理员再解锁相机/品牌/比例。

### I. 画面信息与其它（第二轮对照补入）

> 这一组是**拿你给的原厂截图逐块比对**时补出来的——第一轮只抓了"操作流程"，这些是画面上和菜单里还漏掉的。

**R-23 每个相机画面上的统计块（含复检品）** ⚠️ ｜ 差距 D-37
- 要求（原厂主界面截图）：每路画面**右上角**叠一个统计框，内容是
  `不良品 / 良品 / 良品率 / 复检品`；画面内每个检测对象还显示**编号**（01、02、03…），左上角大号 `OK`。
- **现场确认（2026-11-16）「复检品」口径**：
  > 「不良品会排出，然后我们**会收集起来**，到时候**再放进去做检测**」
  - 即：首次判 NG → 被排出机台 → 人工**集中收集** → 之后**重新上料再测一遍**；
  - 这些"再测的件"计入 **复检品**，与首次检测的良品/不良品**分开统计**。
- 由此推出要实现的（**复检模式**）：
  1. 界面有 **首检 / 复检** 模式切换（一个按钮或下拉），操作员把 NG 件放回去时切到"复检"；
  2. 复检帧的判定结果**单独计数**，显示在统计块第 4 项 `复检品`；
  3. **良率仍按首检算**（复检件不进良率分子分母，否则复检会"污染"良率）；
  4. 另给一个 **复检合格率**（复检件里 OK 的比例），这是这条流程真正的质量指标；
  5. CSV / 结果记录里标注该帧是 **首检还是复检**，方便追溯；
  6. 首检 NG 件被收走时，**NG 计数不能被复检结果冲掉**（否则不良率会凭空变好）。
- 现状：有 OK/NG/良率/耗时统计，**无复检概念、无模式切换、无复检合格率、无画面内对象编号**。
- **调试员照片观察（2026-11-16）**：单路画面里就有 **10~16 个检测对象**（两排 PIN，编号 01、02… 贴在每个框旁），
  字号很小但必须可读 → 编号要**字号自适应 + 重叠避让**，并能切"只显示编号不显示框"（否则画面被框糊死）。
- 验收：切到复检模式跑 10 件（5 OK / 5 NG）→ 统计块"复检品=10"，良率不变，复检合格率 50%，CSV 有"首检/复检"列。

**R-24 静态画面模式** ⚠️ ｜ 差距 D-38
- 要求（超级管理员截图）：`静态画面 开/关` —— 不接相机时用一张静态图调试/演示。
- 现状：可以用"图片回放（单张图循环）"等效，但界面没有这个开关，现场不知道这么用。
- 验收：界面上能一键切"静态画面"（选一张图，帧率不限，其他流程照跑）。

**R-25 判定类型覆盖：有无 / 尺寸 / 缺料** ⚠️ ｜ 差距 D-39
- 要求（说明第 3 节）：规则要能配「有无、尺寸、缺料」等判定条件。
- 现状：能力上已覆盖（数量=有无、面积/距离=尺寸、数量+面积组合=缺料），但**界面文案与规则类型里看不出来**，现场会以为不支持。
- 验收：规则类型下拉有「有无（数量）」「尺寸（距离/面积）」「缺料（缺几个）」这几项，映射到现有算子。

**R-26 检测区域内的"无需检测空白区域"（忽略区）** 🟡 **现场不需要，功能保留** ｜ 差距 D-40
- 说明原文：「框选出产品需要检测的区域，**区分检测区域和无需检测的空白区域**」。
- **现场确认（2026-11-16）**：「**不参与检测**，但是你的功能可以放着」
  → 当前产线**不需要**忽略区；功能**保留**（做成可选开关，默认关），**不排期**，等真遇到治具/反光/丝印干扰再启用。
- 现状：只有"框内检测、框外不检测"（ROI 本身）；ROI 内部的忽略块不支持。

**R-27 任务导航式向导** ❌ ｜ 差距 D-38（与 R-24 同一批）
- 要求（原厂左侧栏）：`连接相机 → 检测参数设置 → IO 参数控制 → 完成` 的四步向导。
- 现状：我们是一屏全功能（工具条 + 右侧面板），没有向导；老操作员会觉得"不知道从哪开始"。
- 优先级：P2（不影响功能，只影响上手）。

## 4. 实现思路（技术方案草稿，落地前补 ADR）

**跟踪框（R-14/R-15）——✅ 已实现（`visionapp/tracking.py`）**

```
每帧：① 在"跟踪框"区域用 match_template（或灰度投影）找产品特征 → 得到 (dx, dy)
      ② 把所有检测框的 ROI 与已算出的点坐标整体平移 (dx, dy)
      ③ 再跑原有 Pipeline → 数值与判定
```
- 好处：算子不用改；跟踪失败时（相似度 < 阈值）可直接判 NG/报警，避免错判。
- 配方新增字段：`track: {roi: [...], src_item: "template_id", min_score: 0.7, apply_to: ["all"] | [item_id...]}`。
- 界面：工具条加"跟踪框"绘制模式 + "跟踪设置"对话框（起始/终止对象、跟踪对象）。

**抓取位置（R-08）**：`find_blobs` 增加 `pick = {polarity: dark|light, zone: bottom|lower|center|upper|top}`，取斑块边界的对应位置作为测量点。

**X/Y 标定（R-16）**：配方 `calibration` 从 `mm_per_px` 扩展为 `{x_mm_per_px, y_mm_per_px}`（旧字段兼容），界面加"输入设定值/实测值反算"。

**三级权限（R-22）**：`security.py` 角色从 2 个扩为 3 个（production/admin/super），启动默认 production（只读运行），密码解锁后按角色放开控件。

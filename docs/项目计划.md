# 开源视觉检测系统 —— 项目计划（VisionApp）

> 目标：用开源栈复刻/替代原 In-Vision 的核心检测能力，支持多机位，开发机 macOS + 生产机 Windows，
> 在生产机上独立运行（不再依赖原程序、不需要 HASP 加密狗）。

---

## 一、范围与验收标准

**一期范围（必做）**

| 模块 | 内容 |
| --- | --- |
| 取图 | 开发相机（MaixCam Pro）+ 生产工业相机，统一抽象的帧源接口 |
| 检测算子 | 模板匹配、Blob/面积、卡尺测边、直线/圆拟合、两点距离、角度、正位度、参差度、相似度比对、缺角/有无 |
| 判定 | 每项按公差判 OK/NG，整件汇总判定，可自定义公式 |
| 配方 | 每个型号一套配方（ROI + 参数 + 阈值），保存/加载/克隆 |
| 多机位 | 多相机并发采集，每个机位独立配方，结果按规则合并 |
| 界面 | 实时画面、ROI 编辑、参数面板、结果表、运行日志 |
| 输出 | CSV/JSON 结果、NG 截图、屏幕叠加显示 |
| 部署 | Windows 生产机免安装运行；macOS 开发机可调试 |

**一期不做（后续再说）**：MES/数据库对接、AI 训练平台、硬件 IO 卡与 PLC、视频录像。

**验收**：同一批黄金样张（同一相机、同一光照）分别用原 In-Vision 和新系统跑，逐项数值与 OK/NG 判定一致（允许在标定换算后等效，偏差在测量重复性范围内）。

## 二、技术选型

| 层 | 选型 | 许可 | 理由 |
| --- | --- | --- | --- |
| 语言 | Python 3.11 | PSF | 视觉生态最好，与 MaixPy 同语言，跨平台 |
| 界面 | PySide6 (Qt 6) | LGPL | 跨 Win/mac，控件齐全，动态链接可商用 |
| 图像算法 | OpenCV (opencv-python) | BSD-3 | 标定、匹配、形态学、拟合全都有 |
| 数值 | numpy | BSD | — |
| 打包 | PyInstaller（onedir） | GPL+例外 | Win/mac 都能出绿色包 |
| 测试 | pytest + 黄金样张回归 | MIT | — |
| 可选 AI | onnxruntime（跑 ONNX 模型） | MIT | 免 Python 依赖，离线推理 |
| 避免 | Ultralytics YOLO | **AGPL-3.0** | 商用要买授权，产品里不用 |

> 说明：**macOS 只做开发/调参**。工业相机 SDK（海康 MVS、大恒 Galaxy 等）基本只提供 Windows 驱动，
> 生产环境一律用 Windows；mac 上跑 MaixCam + 图片 + 算法验证完全够用。

## 三、相机抽象层（关键设计）

```python
class Frame:                 # 统一帧对象
    bgr: np.ndarray          # BGR uint8, HxWx3
    ts_ns: int               # 采集时间戳
    index: int               # 帧序号
    meta: dict               # 曝光/增益/触发源等

class FrameSource(ABC):
    def open(self) -> None: ...
    def read(self, timeout_ms: int) -> Frame: ...
    def close(self) -> None: ...
    @property
    def info(self) -> SourceInfo:   # 分辨率/品牌/序列号/是否支持软触发
        ...
```

实现（一期）：

| 适配器 | 用途 | 说明 |
| --- | --- | --- |
| `UvcSource(index)` | MaixCam Pro（UVC 模式） | `cv2.VideoCapture(0)`，跨平台最省事 |
| `RtspSource(url)` | MaixCam Pro（RTSP/MJPEG） | `cv2.VideoCapture("rtsp://...")`，参数控制更全 |
| `FolderSource(path)` | 离线回放/回归测试 | 按序读图，做黄金样张比对 |
| `PylonSource` | Basler 工业相机 | pylon Python 包 |
| `HikSource` / `GalaxySource` | 海康/大恒 | 厂商 SDK 的 Python/.NET 封装，Windows 生产机 |

探测结果：MaixCam Pro 当前以 **USB 复合设备（VID_359F&PID_2120）** 接入，系统里同时出现
`UsbNcm Host Device`（网络，可走 RTSP/MJPEG）和 `COM1`（串口调试）。
M0 阶段先确认固件版本与 UVC 是否可用，两条路都打通，取快的那条。

## 四、处理流水线与配方模型

```
采集帧 → 预处理（畸变校正/白平衡/光照归一） → 检测项[ROI_i] → 判定 → 输出（界面叠加 + CSV + 截图）
```

**检测项（Item）统一结构**

```jsonc
{
  "id": "pin1_pitch",
  "type": "distance_pp",          // 算子类型
  "roi": [x, y, w, h],            // 搜索区域（像素）
  "params": { "edge_threshold": 40, "polarity": "dark2light", "search_width": 30 },
  "output": { "name": "X方向距离", "unit": "mm", "scale": "calib1" },
  "judge": { "kind": "range", "min": 1.98, "max": 2.02 }
}
```

**算子库 V1**（对应原程序 `.HPro` 里的检测类型）

| 算子 | 说明 | 原程序对应 |
| --- | --- | --- |
| `match_template` | 模板匹配定位 | 图像比对 / 相似度 |
| `blob_area` | 连通域面积计数 | 面积 / 有-无 |
| `caliper_edge` | 卡尺找边（一维灰度投影） | 边缘/线端 |
| `line_fit` / `circle_fit` | 直线/圆拟合 | 圆、线、中点 |
| `distance_pp` / `distance_ll` | 点-点、线-线距离 | PIN间距、X/Y方向距离 |
| `angle_ll` | 夹角/角度 | 角度测量 |
| `position_dev` | 正位度（相对基准的偏移） | 正位度 |
| `coplanarity` / `stagger` | 参差度（相对最小值的差） | 参差度 |
| `missing_corner` | 缺角检测 | 缺角 |
| `similarity` | 归一化相关系数 | 图像相似度 |

**配方文件**：`recipes/<型号>.json`（含标定引用、机位号、阈值、版本号），支持"另存为/克隆"做多型号。

**多机位**：`stations: [{camera: "cam1", recipe: "..."}, {camera: "cam2", recipe: "..."}]`，
每机位一个采集线程 + 一个检测线程，结果按 `merge: "all_ok" | "per_station"` 合并。

## 五、与原程序的一致性保证（重点）

原程序资产很全，可以把"运行逻辑"完整转成文档和代码：

| 资产 | 用途 |
| --- | --- |
| `.HPro` 模板（纯文本，首行=机位数） | 写 **hpro importer**：把旧模板读成我们的配方 |
| `HunterxSys.ini`（400+ 参数） | 参数映射表：像素比例、相机比例、触发、输出字段 |
| `In-Vision.pdb` / `.map`（完整符号） | 逻辑参考：函数名与调用流程，用于确认算法细节 |
| `Bin\0121.bmp`、`Data\AdminTime` 记录 | 黄金样张与历史结果来源 |

**验证方法**：同一张图，用原程序记录每项数值 → 新系统跑 → 逐项比对（回归脚本自动出差异表）。
输出交付物：《模板语法与判定逻辑说明》《参数映射表》《一致性测试报告》。

## 八、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 本机与生产机都**不联网** | 装不了 Python / 依赖 | 需在联网机做 **wheelhouse（离线包）**；我准备好 `requirements.txt` + 下载脚本 |
| macOS 工业相机驱动缺 | mac 上不能测生产相机 | mac 只做开发；生产固定 Windows |
| 开发相机与生产相机差异（触发、曝光、畸变） | 参数不可直接迁移 | 相机适配器 + 标定分离；配方绑定"相机型号 + 标定文件" |
| 复刻一致性难 | 判定不一致就可能误判 | 黄金样张先行，逐项比对；关键项人工复核阈值 |
| 性能 | Python 处理大图可能慢 | numpy/OpenCV 向量化、ROI 裁剪、必要时多进程 |
| 授权合规 | 商业风险 | 不碰原程序二进制；只用 BSD/LGPL/MIT 许可组件 |

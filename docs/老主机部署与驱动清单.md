# 老检测机部署与驱动清单（先跑检测脚本，再决定装什么）

> **结论先说**：`SDK ≠ 驱动`。相机要**驱动**（让 Windows 认识相机），我们的程序要 **SDK**（MvCameraControl.dll + py 文件，让程序能取图）。两样都要，但装的位置和顺序不同。
> **更关键的是系统版本**：我们现在的 exe 是 **Python 3.12 + Qt 6.12** 打的，官方要求 **Windows 10 及以上（64 位）**。
> 10 年前的老机器如果是 **Win7 / Win8.1 / 32 位**，这个 exe **打不开**——必须先确认，再决定是升级系统还是我另出一个 Qt5 兼容版。

---

## 0. 一句话说清 SDK 与驱动

| | 驱动（Driver） | SDK |
| --- | --- | --- |
| 是什么 | 让 Windows 认识相机硬件的系统组件（`usbvideo.sys` 类 / 厂商 USB 驱动） | 厂商提供的**编程接口库**：`MvCameraControl.dll` + 一堆 `.py` 封装 |
| 谁需要 | 操作系统 | **我们的程序**（VisionApp.exe） |
| 装在哪 | 系统（设备管理器里能看到相机） | 放进程序目录 `sdk\mindvision\`（exe 会自己找） |
| 怎么装 | 跑厂商**驱动安装程序**（装完插相机就能在设备管理器看到） | 从安装目录**拷文件**，不用安装 |
| 不装的后果 | 设备管理器里是黄色感叹号，任何软件都取不到图 | 相机在系统里正常，但**我们的程序**报"找不到 SDK" |

**千兆网（GigE）相机**：一般**不用装驱动**（走标准网卡），只要把网卡设成相机同网段 + 开巨帧（Jumbo Frame 9014）+ 关防火墙；可选装厂商 filter 驱动提升吞吐。

## 1. 第一步：在老机器上跑检测脚本（1 分钟，不改任何东西）

把仓库里的 `tools\check_env.ps1` 拷到老机器，右键 **"使用 PowerShell 运行"**（或 `powershell -ExecutionPolicy Bypass -File check_env.ps1`），把输出（或生成的 `env_report.txt`）发我。

它会报告：系统版本/位数、CPU/内存/磁盘、VC++ 运行库、USB 控制器（是否 USB3）、已装的相机软件与驱动、`MvCameraControl.dll` 位置、网卡与巨帧设置。

> 手快也可以只看两个数：`winver`（系统版本）、`系统属性 → 系统类型`（64/32 位）。

## 2. 按系统版本决定方案

| 老机器系统 | 我们的 exe 能跑吗 | 方案 |
| --- | --- | --- |
| **Windows 10 / 11（64 位）** | ✅ 能 | 直接按 §3 装 |
| **Windows 8.1（64 位）** | ⚠️ 不一定（Qt6 官方要求 Win10） | 先试跑；跑不起来我出 Qt5 兼容版 |
| **Windows 7 SP1（64 位）** | ✅ **已提供 32 位包**（32 位程序在 x64 上照跑） | 用 `dist_x86\VisionApp-x86\`：**能直接用现场那份 `MVCAMSDK.dll`**；先装 **KB2999226** 补丁 |
| **Windows 7 SP1（32 位）** | ✅ **已提供 32 位包** | 同上，用 `dist_x86\VisionApp-x86\` |
| **32 位系统（任何版本）** | ❌ 不能 | 需 32 位工具链重打（Python 3.8 x86 + Qt5 x86 + opencv x86），或换 64 位系统 |

> 老机器 10 年（约 2015~2016 年）：如果是原装 Win7，**大概率属于后两种情况**，务必先跑 §1 的脚本。

## 3. Windows 10/11 x64 上要装的东西（按顺序）

| # | 装什么 | 版本要求 | 说明 |
| --- | --- | --- | --- |
| 1 | **Visual C++ 2015-2022 运行库（x64）** | 14.29 以上 | 我们的 exe **已内置** VCRUNTIME140/MSVCP140/ucrtbase，一般不用装；但**相机 SDK 的安装器**和部分旧驱动需要，装上更稳 |
| 2 | **相机驱动** | 用**与相机同年代**的驱动包 | MindVision 官网按型号下载；**老机器别装最新版驱动**（新版常要求 Win10 1909+） |
| 3 | **MVSDK 文件**（不是安装） | 与驱动同版本 | `MvCameraControl_class.py`、`CameraParams_header.py`、`CameraParamsConst.py`、`MvErrorDefine_const.py`、`PixelType_header.py`、`MvCameraControl.dll`（**x64**）→ 拷到 `sdk\mindvision\` |
| 4 | **VisionApp.exe** | 我们的包 | 整个 `dist\VisionApp` 文件夹拷过去，放 **纯英文路径**（如 `D:\VisionApp`） |
| 5 | 网卡设置（GigE 相机才要） | — | 同网段 IP、巨帧 9014、关闭节能/防火墙 |

### 驱动版本怎么选（"别人家的老机器"专用）

- 优先用**老机器上现在能用的那个驱动版本**（原厂软件能出图 = 驱动 OK）——**已经在用的就不要动**；
- 如果必须重装：选**该型号发布年份的驱动**（2015~2018 版），别下最新；
- 下载页若只有最新版：联系厂商要"历史版本"，或直接从老机器的 `C:\Windows\System32\drivers` + 安装目录里**备份现有驱动**（用 `pnputil /export-driver` 可以导出）。

## 4. 装完怎么验证（3 步，10 分钟）

| 步 | 动作 | 通过标准 |
| --- | --- | --- |
| 1 | 设备管理器 → 图像设备/相机 | 能看到相机型号，**没有黄色感叹号** |
| 2 | 用厂商自带工具（如 MindVision 的 Demo）打开相机、抓一帧 | 能出图、能设曝光 |
| 3 | 跑我们的检查：`VisionApp.exe --single --source synthetic --frames 2 --run 1` 先确认程序本身能跑；再在界面里 相机 → 工业相机 MindVision → 连接 | 弹出"连接成功 WxH"，点开始能出图 |

## 5. 老机器性能提醒（10 年前的 CPU）

| 风险 | 说明 | 处理 |
| --- | --- | --- |
| 多路相机跑不动 | 6 路 × 500 万像素 + 检测，老 CPU 可能只有几 FPS | 先按 1~2 路试；不够就降分辨率/ROI 裁剪，或只跑检测区域 |
| USB3 带宽 | 老机器可能只有 USB2 口（USB3 相机插 USB2 会降速/掉线） | 用 `check_env.ps1` 看有没有 USB3 控制器；没有就加 PCIe USB3 卡或换 GigE 相机 |
| 系统补丁 | Win7 缺 UCRT 补丁（KB2999226）会导致 Qt 起不来 | 升级 Win10 最省事；坚持 Win7 就装 KB2999226 + KB2533623 |
